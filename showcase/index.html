Architecture

How NSA embeds policy into neural computation

01

Typed Activations

Every activation is decomposed into a semantic stream m (meaning) and a state stream σ (permissions, trust, provenance).

h = (m, σ) where m ∈ ℝd_model, σ ∈ ℝd_state
m — Semantic
Content, syntax, task
σ — State
Security, provenance, trust
02

State Lattice

Security labels form a bounded lattice with a strict partial order. Information can only flow upward (toward more restricted states).

SYSTEM σ=5
PRIVATE σ=4
CONFIDENTIAL σ=3
TRUSTED σ=2
PUBLIC σ=1
UNTRUSTED σ=0
PRIVATE → SYSTEM ✓ Allowed (upward)
PRIVATE → PUBLIC ✗ Forbidden (downward)
03

State-Aware Attention

An additive state mask Mstate is injected into the attention scores. When a query's level is lower than a key's level, the mask applies −∞, zeroing out that attention weight after softmax.

M(i,j) = −∞ when level(query_i) < level(key_j)

Deep Dive

The full h = (m, σ, ν) architecture

NSA provides three distinct enforcement layers — hard algebraic constraints, operational state tracking, and learned value alignment.

🔒

Hard Constraints σ

State algebra on a bounded lattice. Attention mask applies −∞ to forbidden key→query pairs. This is algebraic impossibility — no gradient, no prompt, no adversarial input can override it.

PRIVATE key → PRIVATE query → PERMITTED
PRIVATE key → PUBLIC query → BLOCKED (−∞)
📊

Operational State σ

Beyond binary security labels, the state vector tracks multiple dimensions simultaneously via a product lattice:

🔐 Security
📎 Provenance
📈 Confidence
🏢 License Tier
⚖️

Value Layer ν

A learned preference layer that operates within the space of permitted actions. Hard constraints determine what's allowed; the value layer determines what's preferred.

Action A → violates σ → REJECT (hard)
Action B → safety=0.82 → utility=0.77
Action C → safety=0.91 → utility=0.81 ← CHOSEN
