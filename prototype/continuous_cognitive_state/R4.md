# R4 — Dynamic NSA-Governed Action Boundary

R4 connects live model-generated action proposals to a deployment-supplied capability policy. No action names are hard-coded and no actuator is simulated here.

The model produces a typed proposal at runtime. The trusted runtime evaluates it against capabilities, risk, confidence, reversibility and optional human approval. Only an ALLOW decision may be passed to a real actuator integration supplied by the deployment.

```text
live cognitive state
      |
      v
Ollama reasoning
      |
      v
structured action proposal
      |
      v
NSA governance boundary
   /       |        \
ALLOW    HOLD      DENY
  |        |          |
real     wait       reject
actuator / approval
```

## Dynamic requirement

The runtime must not contain a fixed mapping such as `"send_email" -> allow`. Capabilities and thresholds are runtime configuration. The model can request a capability but cannot grant itself one.

R4 therefore tests the real architecture: changing the live cognitive context can produce different model proposals, and the same proposal can receive different governance outcomes when deployment policy changes.

## Safety boundary

The prototype deliberately stops at the governance decision. Real actuator plugins must be separate, capability-scoped integrations and must receive only an already-authorized proposal.
